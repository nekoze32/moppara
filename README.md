# Moppara — もっぱら、食事管理だけ

チャットに **写真か一言を送るだけ** で記録できる食事管理アプリ。
note の記事（[Gunto](https://note.com/kajiken0630/n/nf51df1810217)）と同じ考え方で、
「カロリー計算が面倒で続かない」を、入口をチャット1本に絞ることで解いている。EWG業務外の個人開発。

- **サーバー無し**（静的PWA）。記録は端末のIndexedDBだけに置く
- **APIキーは端末の中**。送信先はGoogleかAnthropicのAPIだけ
- **プロバイダを設定で差し替えられる**。無料枠のGeminiで始めて、あとからAnthropicへ移せる

---

| プロバイダ | 月額の目安 | 学習利用 |
|---|---|---|
| Gemini Flash（無料枠） | **0円** ／ 1日1,500回まで | **無料枠は入力がGoogleの製品改善に使われる** |
| Anthropic `claude-haiku-4-5` | **約110円** ／ 写真1枚 約0.6円 | 使われない |
| Anthropic `claude-sonnet-5` | 約250円 | 使われない |
| （参考）あすけんプレミアム | 580円（2026年9月改定） | — |

写真は長辺800pxまで縮めてから送るので、1枚あたりの画像トークンは900前後。
1日3枚＋相談3回で上の数字になる。

## 使い始める

### 1. APIキーを取る

- Gemini … <https://aistudio.google.com/apikey>（Googleアカウントで発行。クレカ不要）
- Anthropic … <https://console.anthropic.com/settings/keys>（クレジット購入が要る）

### 2. アプリを開いて設定する

はじめて開くと**APIキーだけ**を聞かれる。無料で始めるならGeminiを選んでキーを貼るだけ。

身長・体重・目標は、そのあと**チャットが会話で聞く**。フォームを埋める必要はない。
全部そろった時点で、1日の上限とPFCをアプリが計算して提示する（この数字はAIに言わせない。
聞き取り中のAIはまだ計算できず、必ず外すため）。

あとから直すときは設定タブ。モデル名が合わないときは「使えるモデルを取得」を押すと、
そのキーで使えるものが一覧になる。

### 3. スマホのホーム画面に置く

公開URLをiPhoneのSafariで開き、共有ボタン →「ホーム画面に追加」。
アプリとして全画面で立ち上がり、カメラもそのまま使える。

## 使い方

すべて **チャットタブの入力欄** で受け付ける。

| 入力 | 起きること |
|---|---|
| 料理の写真 | 料理名・分量・カロリー・PFCを推定 → 確認カードが出る → 数字を直して「記録する」 |
| 「かけそばとおにぎり1個」 | 同上（写真なしでも同じ） |
| 「いつものプロテイン」 | 登録済みの「いつもの」から数値をそのまま使う |
| 「体重72.4」 | その日の体重として即記録 |
| 「30分走った」 | 消費カロリーを見積もって即記録（上限に加算） |
| 「今夜ゆで太郎で何を食べていい？」 | 残りカロリーとPFCに収まる**品目と個数**を返す（記録はしない） |
| 「回転寿司であと何皿？」 | 同上 |

画面上部の帯には、常に **残りカロリーとP/F/Cの残り** が出ている。タップで「今日」へ。

確認カードの kcal 欄は直せる。直すとP/F/Cが比例して動く。
記録したあと「いつもの に登録」を押すと、次から名前で呼び出せる。

## iPhoneのヘルスケアとつなぐ

WebアプリからHealthKitは読めない。ショートカット経由で数値を渡す。

1. ショートカットアプリで新規ショートカットを作る
2. **ヘルスケアサンプルを検索** → 種類：アクティブエネルギー／期間：今日／まとめる：合計
3. 体重も入れるなら、もう1つ **ヘルスケアサンプルを検索** → 体重／最新の1件
4. **URLを開く** を置き、`https://<公開URL>/#health?ae=[合計]&w=[体重]` の形にする
5. オートメーションで「毎日 22:00」に実行

`ae` だけ、`w` だけでも動く。開くとアプリが受け取って記録し、その日の上限に反映する。
同じ日に何度実行しても、ヘルスケア由来の運動は上書きされる（二重計上しない）。

## 上限カロリーの決め方

```
基礎代謝(BMR)  Mifflin-St Jeor 式
生活消費(TDEE) = BMR × 活動係数（座位1.2／軽い1.375／中1.55／高1.725）
目標の赤字     = 必要ペース(kg/週) × 7200 ÷ 7
その日の上限   = max(生活消費 − 赤字, 下限) + 運動で消費した分
下限           = max(BMR, 男1500 / 女1200 kcal)
```

- 目標の日を入れると必要ペースは自動計算。空なら手入力のペースを使う
- 下限に当たったときは画面にその旨を出す（目標どおりの赤字だと基礎代謝を割る、という警告）
- 週1kgを超えるペースを要求された場合も警告を出す
- **運動を別に記録するなら活動量は「座位中心」にする**。でないと二重に足される

PFCは P（目標体重×g/kg）→ F（総カロリーの%）→ 残りを C の順で決める。設定で変えられる。

## 中身

ビルド不要。素のES modules。

```
index.html            画面の枠（残量バー／4タブ）
styles.css            配色トークン（ライト・ダーク）
manifest.webmanifest  PWA
sw.js                 Service Worker（ネット優先・圏外はキャッシュ）
icons/                アイコン
src/
  app.js              起動・タブ切替・残量バー・#health の受け口
  store.js            設定と「今日の集計」。変わったら購読者へ通知
  db.js               IndexedDB（meals / weights / activities / presets / chat / kv）
  nutrition.js        BMR・TDEE・上限・PFC・移動平均
  prompts.js          システムプロンプトと、毎回渡す「いまの状況」
  ai.js               Gemini と Anthropic の差を吸収する層
  views/chat.js       チャットと確認カード
  views/today.js      今日（リング・食事・体重・運動・いつもの）
  views/trend.js      推移（体重の線・摂取カロリーの棒・数値表）
  views/settings.js   設定
```

AIには毎回、**その時点の状況**（上限・摂取・残り・今日の記録・直近の平均・体重の推移・いつもの一覧・好み）を
テキストで渡している。だから「残りで何が食べられる？」に具体的に答えられる。

出力は必ず1つのJSONに揃えている（Geminiは `responseSchema`、Anthropicは強制ツール呼び出し）。

```
{ reply, meal | null, weight | null, activity | null }
```

`meal` が入っていれば確認カード、`null` なら返事だけ。体重と運動は確認なしで即記録する。

### グラフの配色

`dataviz` の `validate_palette` で検証済み。

| モード | 上限の中 | 超えた分 | normal ΔE | CVD ΔE | 対サーフェス |
|---|---|---|---|---|---|
| ライト | `#C2552F` | `#8A3A6B` | 16.7 | 13.5 | PASS |
| ダーク | `#D9744E` | `#B173C9` | 18.7 | 11.9 | PASS |

当初は超過分を `--danger`（`#B23A2E`）にしていたが、accentとの normal ΔE が 6.7 で
「全色視でも見分けがつかない」判定だったため差し替えた。

## ローカルで動かす

```bash
python -m http.server 8791 --directory moppara
```

`http://localhost:8791/` を開く。`.claude/launch.json` に `moppara` として登録済み。

## 出し入れ

設定タブの **データ** から JSON で書き出し／読み込み。
**書き出したファイルにAPIキーは含まれない**。
記録はブラウザのストレージにしかないので、サイトデータを消すと一緒に消える。ときどき書き出しておくこと。
